# 原理与排错：为什么改了却不生效

这份文档记录本项目踩过的所有坑。**改汉化前请先读一遍**，能省掉几小时。

---

## 1. 两套机制，各管一半

Autopsy 基于 NetBeans 平台，界面文字有两条完全不同的来源：

| 来源 | 存放位置 | 谁在用 | 改法 |
|---|---|---|---|
| **ResourceBundle** | jar 内 `xxx/Bundle_zh_CN.properties` | 95% 的界面文字（按钮、标题、提示、列头） | 加 `Bundle_zh_CN.properties`，键与 `Bundle.properties` 一致 |
| **Layer（layer.xml）** | jar 内 `layer.xml` 或 `META-INF/generated-layer.xml` | 菜单栏、工具栏、右键菜单的结构与名称 | 加 `displayName` 子元素，或改文件夹名 |

两条链路互不相干：bundle 改对了菜单名也不会变，反之亦然。

---

## 2. ResourceBundle 链路

### 2.1 加载规则

```java
// 类里的典型调用
NbBundle.getMessage(SomePanel.class, "SomePanel.title.text");
// → 查 SomePanel 所在包的 Bundle_zh_CN.properties，再退 Bundle.properties
```

- 文件必须是 **`Bundle_zh_CN.properties`**，与 `Bundle.properties` 同目录。
- 内容必须是 **ASCII 转义的 `\uXXXX`**（NetBeans 用 ISO-8859-1 读取，直接写中文会乱码）。
- 键必须与英文原文一致；**可以多出键**（如菜单路径键），但不能少。

### 2.2 验证方法

```bat
python scripts\loadtest_all.py
```

它用 Autopsy 自带 JRE，对每个 jar 执行 `ResourceBundle.getBundle(name, Locale.CHINA)`，逐个报中文键数。任何包加载失败或 0 中文都会报出来。

## 3. Layer 链路（菜单为什么会英文）

### 3.1 菜单名是怎么来的

`org-netbeans-core-windows.jar!MainWindow.createMenuBar()`：

```java
JMenuBar bar = getCustomMenuBar();          // 系统属性 netbeans.winsys.menu_bar.path，Autopsy 未设置
if (bar == null) bar = new MenuBar(null);   // → 取 SystemFileSystem 的 Menu 文件夹
```

`MenuBar$LazyMenu.updateProps()`：

```java
Mnemonics.setLocalizedText(this, master.getNodeDelegate().getDisplayName());
```

也就是说：**菜单名 = 该文件夹节点的 displayName**。而节点的 displayName 依次取自：

1. 文件夹的 `displayName` 属性（layer 里写成 `<attr name="displayName" stringvalue="…"/>`）；
2. `SystemFileSystem.localizingBundle` 指向的包中、以**文件夹路径**为键的值（如 `Menu/View`）；
3. 都没有 → **直接用文件夹名**（`View`、`Tools`…）。

`Menu/Case` 之所以一直是中文，是因为 Autopsy 自己的 layer 给它配了 `localizingBundle` 和 `Menu/Case=案件`。

### 3.2 正确改法

```xml
<folder name="Menu">
  <folder name="View">
    <attr name="displayName" stringvalue="视图(&amp;V)"/>   <!-- 注意 & 必须转义成 &amp; -->
    ...
```

工具：

```bat
python scripts\patch_layer_names.py --dry-run
python scripts\patch_layer_names.py
```

它会用 expat 解析，按**完整路径**（`Menu/View` 而不是所有叫 `View` 的文件夹）定位，幂等可重复执行。

### 3.3 三个致命细节

| 细节 | 后果 |
|---|---|
| `&` 未转义 | `<attr stringvalue="视图(&V)"/>` 让 layer.xml 变成非法 XML，模块加载失败 |
| 用正则找 `<folder name="View">` | 会命中 Toolbars/View、Shortcuts/View，改错地方（`Menu/Case` 名字唯一反而成功，造成「部分中文」的假象） |
| 空文件夹边界 | `core-ui` 里的 `Menu/View` 是空文件夹（`</folder>` 紧跟），按「下一个 `<file>`」找属性区会越界误判 |

## 4. ★ 最大的坑：NetBeans layer 缓存

### 4.1 现象

- bundle 改动生效（启动窗口标题是中文）；
- layer 改动**永远不生效**（菜单始终英文）；
- 甚至把英文原文 `Bundle.properties` 全量改成中文也没用；
- 反复重启、换 jar、改文件夹名，截图**逐字节相同**。

### 4.2 原因

NetBeans 把**合并后的 layer** 缓存下来了：

```
%LOCALAPPDATA%\autopsy\Cache\dev\all-layers.dat      ← 合并后的菜单结构
%LOCALAPPDATA%\autopsy\Cache\dev\localeVariants      ← 语言变体索引
%LOCALAPPDATA%\autopsy\Cache\dev\all-resources.dat   ← 资源索引（可达 200 MB）
```

只要缓存存在，程序就按缓存里的旧结构建菜单，**不再读 jar 里的 layer.xml**。本项目的缓存是安装当天（2026-05-05）生成的，之后一直没失效。

### 4.3 解决

关闭 Autopsy，删除 `%LOCALAPPDATA%\autopsy\Cache\dev\*`，重启。首次重建约 60–90 秒。

`install_pack.py` / `apply_to_root.py` 已内置 `clear_nb_cache()`，安装后自动执行。

> 多份 Autopsy 安装共用同一个 `%APPDATA%\autopsy` 与 `%LOCALAPPDATA%\autopsy\Cache`，**切换安装后必须再清一次**。

## 5. 排查决策树

```
界面文字是英文
├─ 是菜单栏 / 工具栏 / 右键菜单？
│   ├─ 是 → 查 layer：patch_layer_names.py --dry-run 看有没有目标文件夹
│   │        └─ 改完必须清缓存，否则一定不生效
│   └─ 否 → 查 bundle：report_remaining.py 看这个键在不在 locales/
│            ├─ 不在 → export_batchN.py 导出 → 翻译 → add_bundle.py
│            └─ 在   → loadtest_all.py 看 jar 内能否加载
│                     ├─ 加载失败 → 检查 \uXXXX 转义 / 文件名
│                     └─ 加载正常 → 该字符串可能是代码硬编码（scan_hardcoded.py）
└─ 是整块界面都没中文？
    └─ 确认 jar 被注入过（loadtest_all.py）、locale 参数在（jcmd <pid> VM.system_properties）
```

## 6. 已验证无效的做法（别重复）

| 做法 | 结论 |
|---|---|
| 只补 `Menu/*` 路径键 | 缓存未清时无效；清了以后可作为 displayName 的兜底 |
| 把英文原文 `Bundle.properties` 全量改成中文 | 无效。`_zh_CN` 优先级更高，且菜单不走 bundle |
| 直接改文件夹名（`Menu/Help` → `Menu/帮助`） | 清缓存后有效，但会与其它层合并出**重复菜单**，不推荐 |
| 用 `Add-Type` / COM 抓屏验证 | 被安全策略拦截；改用 `tools/shot_menu2.py`（ctypes + GDI） |
| 改完直接重启就以为生效 | 必须清缓存，这是本项目最大的时间黑洞 |

## 7. 自证 UI 的方法（不用问用户）

```bat
python tools\shot_menu2.py <PID> 160 out.bmp
```

用 ctypes 调 `GetWindowRect` + `BitBlt` 从屏幕 DC 取窗口顶部，只截目标进程的窗口，不涉及桌面其它内容。配合 `Get-Process autopsy64` 拿 PID 即可。
